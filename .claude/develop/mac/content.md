# content/ — картинки проекта: как писать и читать

`content/` в корне репо — все картинки проекта: референсы, тесты и результаты работы. Папка в
`.gitignore`, в git не попадает: она тяжёлая, а на референсы у нас нет прав на публикацию. Как
делить её с MSI, решим, когда MSI будет настроен.

## Структура

```
content/
├── references/                  входящее: на что смотрим и на чём учим
│   ├── mila/                    рисунки Милы — основа датасета для LoRA стиля
│   ├── pinterest/               ориентиры с Pinterest — мудборд: для глаз и промптов, НЕ для обучения
│   └── <источник>/              новый источник — новая папка
├── benchmarks/                  проверки моделей и Mac: скорость, сравнение моделей. В игру не идут
│   └── 2026-11-02-smoke/        <дата>-<имя прогона>
│       ├── anima-turbo_room-evening_1.png
│       ├── anima-turbo_room-evening_1.json
│       └── log.jsonl
└── generated/                   результаты работы
    └── 2026-11-03/              <дата прогона>
        ├── drafts/              черновики, поиск идеи
        ├── backgrounds/         фоны
        ├── sprites/             спрайты
        └── edits/               правки
            ├── <модель>_<промпт>_<seed>.png
            ├── <модель>_<промпт>_<seed>.json
            └── log.jsonl
```

Позже появится `datasets/<имя LoRA>/`: отобранные картинки с подписями (`.txt` с тем же именем)
для обучения.

## Имена

- Картинка — `<модель>_<промпт>_<seed>.png`:
  - модель — ключ из [mac/scripts/models.json](../../../mac/scripts/models.json): `anima-turbo`,
    `anima-aesthetic`, `flux3-klein`, `wai-illustrious`;
  - промпт — `id` промпта из файла прогона: что на картинке, например `street-dusk`;
  - seed — число.
- В частях имени — только строчная латиница, цифры и дефис. `_` разделяет части.
- Дата — `ГГГГ-ММ-ДД`, день запуска прогона. Прогон, перешедший за полночь, остаётся в одной
  папке.
- Рядом с картинкой лежит `.json` с тем же именем — промпт и все настройки. В папке есть
  `log.jsonl`: те же записи по строке на картинку, плюс загрузка моделей (`"kind": "warmup"`).

### Что в `.json`

| Поле                                 | Что                                                             |
| ------------------------------------ | --------------------------------------------------------------- |
| `run`, `purpose`                     | имя прогона и назначение                                        |
| `model`, `model_name`                | ключ модели и её название в Draw Things                         |
| `prompt_id`, `seed`, `size`          | какой промпт, seed, фактический размер `[ширина, высота]`       |
| `time`, `seconds`, `power`           | когда, сколько секунд, от сети (`ac`) или батареи (`battery`)    |
| `peak_footprint_mb`, `swap_growth_mb` | пик памяти Draw Things и рост свопа                            |
| `payload`                            | **ровно тот запрос, что ушёл в Draw Things**: `prompt`, `negative_prompt`, файл модели, шаги, CFG, сэмплер, shift, размер, seed. Повторный запрос с ним даёт ту же картинку |

У файлов первого проверочного прогона (`2026-11-02-smoke`) нет полей `run`, `purpose` и
`model_name`: они появились позже.

## Запись

### Через скрипт — основной путь

1. Файл прогона (JSON): `name`, `purpose`, `models`, `seeds`, `prompts`. Формат описан в
   [mac/README.md](../../../mac/README.md#генерация-из-терминала-api-draw-things), пример —
   [mac/scripts/smoke.json](../../../mac/scripts/smoke.json).
2. `python3 mac/scripts/dt_generate.py <файл прогона>` — скрипт сам кладёт картинки по
   назначению:

   | `purpose`     | Папка                                       |
   | ------------- | ------------------------------------------- |
   | `benchmarks`  | `content/benchmarks/<дата>-<name>/`         |
   | `drafts`      | `content/generated/<дата>/drafts/`          |
   | `backgrounds` | `content/generated/<дата>/backgrounds/`     |
   | `sprites`     | `content/generated/<дата>/sprites/`         |
   | `edits`       | `content/generated/<дата>/edits/`           |

   Другое назначение скрипт не примет: так не появится случайных папок. Новое назначение —
   добавить в `PURPOSES` в скрипте и в эту таблицу.
3. Повторный запуск в тот же день пропускает готовые картинки, а новые seed добавляются рядом.
   На другой день прогон пойдёт в новую папку. Продолжить старый — `--out <его папка>`.
4. Один `id` — один промпт. Изменил текст — дай новый `id` или перерисуй с `--force`, иначе
   скрипт решит, что картинка уже есть.

### Вручную из Draw Things

Картинку, нарисованную в окне Draw Things, экспортировать в `content/generated/<дата>/<назначение>/`
и назвать по тому же правилу. Seed виден в Draw Things. Рядом положить `.json` с тем же
именем: промпт и настройки — конфигурацию Draw Things можно скопировать как JSON.

### Референсы

- **Рисунки Милы** → `references/mila/`. Оригиналы, без правок; имена файлов — любые. Внутри
  можно делить по темам (`characters/`, `locations/`). Оригиналы храним и вне `content/`: папка
  не в git, и это не бэкап.
- **Pinterest и другие чужие картинки** → `references/pinterest/` (или папка своего источника).
  По возможности рядом `sources.md`: файл → ссылка. **Не для обучения**: права у авторов. Это
  мудборд — смотреть, обсуждать, описывать стиль в промптах.
- Для обучения из `references/mila/` позже собирается отдельная копия в `datasets/`, с
  подписями. Оригиналы в `references/` не трогаем.

## Чтение — для людей и Claude Code

- Что нарисовано в какой-то день — `content/generated/<дата>/`, по назначениям.
- С каким промптом и настройками сделана картинка — её `.json`, поле `payload`.
- Перерисовать так же — тот же файл прогона с тем же seed и `--force`. Или отправить `payload`
  в `POST /sdapi/v1/txt2img` как есть.
- Время и память по прогону — `log.jsonl`. Сводные замеры — в
  [mac/benchmarks.md](../../../mac/benchmarks.md).
- **Claude Code** смотрит картинки инструментом Read. Большие (1024² и больше) сначала
  уменьшает в scratchpad: `sips -Z 640 <картинка> --out <scratchpad>/<имя>.png`, чтобы не тратить
  контекст.
- **Claude Code не меняет и не удаляет** ничего в `references/`. В `generated/` и `benchmarks/`
  удаляет только по просьбе.

## Копии в самом Draw Things и очистка

Draw Things не хранит картинки файлами. Всё, что он нарисовал, — и в окне, и через API, вместе
с разогревами, — он пишет в историю проекта: база
`~/Library/Containers/com.liuliu.draw-things/Data/Documents/*.sqlite3`, ≈ 1,7 МБ на картинку.
Нужное уже лежит в `content/`, так что эту историю можно чистить:

```sh
zsh mac/scripts/dt_clean.sh         # показать проекты: размер, сколько картинок в истории
# закрыть Draw Things (Cmd+Q), затем:
zsh mac/scripts/dt_clean.sh --yes   # переместить проекты в Корзину
```

- Модели и настройки приложения лежат отдельно, скрипт их не трогает.
- Картинки, нарисованные в окне и не экспортированные в `content/`, уйдут вместе с историей.
  Перед очисткой экспортировать нужное. Из Корзины всё возвращается.
- Как Draw Things запустится без проекта, проверим при первой очистке и запишем сюда.
- **Claude Code чистит только по просьбе:** сначала запуск без `--yes` и список, затем Павел
  закрывает Draw Things и подтверждает.
