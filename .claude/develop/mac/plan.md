# План: Mac (MacBook Air M4, 24 ГБ)

Составлен 02.11.2026. Здесь только то, что можно сделать на Mac **сейчас** — не дожидаясь
точных спеков MSI, художника и решения по лицензиям. Роль Mac и выбор моделей обоснованы в
[research/](../../research/README.md); установка и настройки — в [mac/README.md](../../../mac/README.md).

## Исходное состояние (проверено 02.11.2026)

- Mac16,12: M4, 10 ядер CPU и 10 ядер GPU, 24 ГБ; macOS 15.6.1.
- Экран 2560×1664 Liquid Retina (P3) — на нём проверяем цвет.
- **Свободно 206 ГБ.** Набору моделей нужно ≈ 30–50 ГБ.
- Не установлено: Draw Things, Krita, Homebrew, `cwebp`. Есть `git` и системный `python3`.

## Главная мысль

Качество картинок зависит от модели, а не от машины. Стиль, анатомию и артефакты одни и те же
веса дают одинаковые и на Mac, и на MSI. **Поэтому сравнение моделей можно целиком провести на
Mac**, пока MSI не готов: медленно, но ≈ 100 картинок — это пара ночных прогонов. Скорость
MSI замерим потом отдельно.

Одно ограничение: Draw Things и ComfyUI — разные движки, и один seed даёт на них разные
картинки. Поэтому всё сравнение делаем в одном движке, на Mac. Результаты Mac и MSI по seed
между собой не сравниваем.

## Шаги

Статусы: ☐ — не начат, ◐ — в работе, ☑ — готов.

### ☐ 1. Draw Things и замеры скорости

- Установить Draw Things из App Store. Убедиться, что версия поддерживает FLUX 3 Image Klein
  (движок v26.1023 от 23.10.2026).
- Скачать модели:
  - Anima Turbo + Aesthetic (Base — позже, для обучения);
  - FLUX 3 Image Klein, 8-bit;
  - Illustrious-чекпойнт — WAI-Illustrious v16, `.safetensors` с Civitai, импорт.
- По желанию — Qwen-Image 2.1 в 4-bit, только для сравнения: лицензия некоммерческая.
- Для каждой модели замерить:
  - время одной картинки в 1024² и 1536×864;
  - пиковую память (Мониторинг системы → Память);
  - время 10 картинок подряд — так виден троттлинг.
- **Результат:** таблица в `mac/benchmarks.md`.
- **Проверка:** подтвердилась ли оценка из ресерча «≈ 2 мин на Anima Turbo», и с какой
  картинки начинается замедление.

### ☐ 2. API Draw Things → Claude Code

- В Draw Things включить HTTP API Server: Advanced → API Server, HTTP, порт 7860, localhost.
- Проверить `curl http://localhost:7860` и одну генерацию через `POST /sdapi/v1/txt2img` (API
  совместим с AUTOMATIC1111).
- Написать скрипт `mac/scripts/` на чистом `python3`, без зависимостей:
  - берёт набор промптов из файла;
  - генерирует с фиксированными seed;
  - сохраняет `модель_промпт_seed.png` и рядом JSON с параметрами.
- Выяснить, можно ли через API переключать модель. Если нельзя — переключать вручную между
  прогонами.
- **Зачем:** сравнение в шаге 4 запускается одной командой и повторяется; Claude Code сможет
  генерировать на Mac сам.
- **Проверка:** скрипт генерирует 3 картинки по файлу с промптами без участия человека.

### ☐ 3. Тестовый бриф и набор промптов — нужен Павел

Без брифа сравнение бессмысленно. Шаг можно вести параллельно с 1–2.

- **Нужно от Павла:**
  - внешность Милы (и 1–2 других персонажей) текстом: возраст, рост, волосы, глаза, одежда,
    характер позы;
  - 5 локаций из сценария;
  - 5–10 картинок-ориентиров стиля — мудборд, только для глаз, не для обучения.
- **Тестовый набор:**
  - 5 фонов: интерьер и экстерьер, день и ночь;
  - 3 спрайта: полный рост, нейтральный фон;
  - 3 правки по инструкции.
- **Шаблоны промптов** под каждую модель:
  - Anima — теги + обычный текст от двух предложений;
  - Illustrious — Danbooru-теги + quality-теги;
  - FLUX 3 Klein — обычный язык.
- Кладём в `prompts/` в корне — это часть общей «библии» для обеих машин.
- **Результат:** `prompts/bake-off.*` — файл, который читает скрипт из шага 2.

### ☐ 4. Сравнение моделей (bake-off)

- 8 промптов (5 фонов + 3 спрайта) × 3 модели (Anima Aesthetic, Illustrious, FLUX 3 Klein) × 4
  seed ≈ 100 картинок. Qwen-Image 2.1 — по желанию, для справки.
- При 1.5–3 мин на картинку это ≈ 3–5 часов. Гонять от сети, частями или ночью.
- Оценка 1–5 по критериям:
  - попадание в стиль semi-realism anime;
  - фон: глубина, свет, перспектива;
  - персонаж: анатомия, руки, лицо;
  - артефакты;
  - следование промпту.
- **Результат:**
  - итоги в `.claude/research/05-bake-off.md`;
  - выбрана основная модель для фонов и для спрайтов;
  - ясно, подходит ли FLUX 3 Klein для аниме.
  - Сами картинки — вне репо, в `~/Pictures/mila-draw-ai/bake-off/`.

### ☐ 5. Правки: edit-модель против inpaint

На лучших картинках из шага 4.

- **FLUX 3 Klein edit**, 5 типовых правок:
  - сменить время суток;
  - убрать объект;
  - добавить объект;
  - поправить руку;
  - сменить одежду.
- Проверить, есть ли в Draw Things bounding box и несколько референсов, или это пока только в
  ComfyUI.
- **Inpaint** в Draw Things той же моделью, что рисовала: выделить → перерисовать.
- **Главный вопрос:** сохраняет ли FLUX 3 Klein стиль картинки от Anima или Illustrious, или
  перерисовывает всё «под себя».
- **Результат:** рецепт «какая правка чем делается» в `mac/README.md`.

### ☐ 6. Прозрачный фон и экспорт в WebP

- Сравнить три способа вырезать спрайт:
  - встроенное в macOS «Удалить фон» (Finder → Быстрые действия);
  - удаление фона в Draw Things, если там есть (проверить);
  - нативный RGBA у Qwen-Image 2.1.
  Критерии: волосы, полупрозрачные края, детали в цвет фона.
- Экспорт: поставить Homebrew и `webp` (`cwebp`). Подобрать параметры:
  - фоны — качество ≈ 85–90;
  - спрайты — с альфой, near-lossless.
- **Результат:** проверенный рецепт «PNG → WebP» в `mac/README.md`.

### ☐ 7. (опц.) Пробное обучение LoRA в Draw Things

- Технический тест, не боевая LoRA: LoRA персонажа на Anima Base по 15–20 картинкам одного
  персонажа из шага 4. Замерить время, нагрев и качество.
- **Зачем:** понять, можно ли учить на Mac, если на MSI окажется RTX 4050 или он будет занят.
  Боевая LoRA стиля — только с датасетом художника.

| Что                                   | Почему                                                              |
