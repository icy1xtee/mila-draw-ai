# План: MSI (Katana 17 B12VFK, RTX 4060 8 ГБ)

Составлен 07.11.2026. Роль MSI и выбор моделей обоснованы в [research/](../../research/README.md);
конфигурация, установка и настройки — в [msi/README.md](../../../msi/README.md). План Mac —
[develop/mac/plan.md](../mac/plan.md).

## Исходное состояние (проверено 07.11.2026)

- Katana 17 B12VFK: i7-12650H, **RTX 4060 Laptop 8 ГБ**, 16 ГБ DDR5 (2 × 8, оба слота заняты).
  Windows 11 Pro 26300.
- **SSD 512 ГБ, свободно 131 ГБ** (после удаления Infinity Nikki — 238 ГБ, см. журнал) —
  главное ограничение. Стартовый набор моделей из ресерча
  (80–120 ГБ) и окружения Python (≈ 20 ГБ) с запасом не влезают. **Новый SSD не покупаем**
  (решение Павла, 07.11.2026): место освобождаем по мере необходимости.
- Есть: драйвер NVIDIA 610.78 (CUDA 13.3), Git 2.56, MSI Center 2.0.71, схема питания «Высокая
  производительность».
- Нет: Python (`python` — заглушка Microsoft Store), uv, ComfyUI, тренеры, `cwebp`, Krita.
- Длинные пути в Windows выключены (`LongPathsEnabled = 0`) — включены в шаге 1.
- Wi-Fi в профиле «Общедоступная» — переведён в «Частную» в шаге 1. Есть VPN-интерфейс `tun0`,
  он может мешать доступу с Mac.
- `content/` на MSI нет. Рисунки Милы (105 PNG) и прогоны Mac лежат только на Mac.

## Главная мысль

MSI нужен для того, чего Mac не может или делает слишком медленно:

1. **Скорость.** Картинка ≈ 1 Мп здесь — секунды, а не минуты (bake-off: 64 картинки за 22
   минуты). Можно перебирать варианты, а не ждать ночь.
2. **Рабочее место Милы — веб-интерфейс** (решение Павла, 07.11.2026). Мила садится с
   задачей («персонаж X»), приносит концепт, референсы и наброски, генерирует через простой
   интерфейс с любого устройства в домашней сети, а Claude ведёт дневник задачи. Всё, что
   умеет ComfyUI и что мы настроим (модели, LoRA, предпромпты, удаление фона, спрайты), —
   кнопками в этом интерфейсе. Подробно — шаг 6 и [web-interface/README.md](../../../web-interface/README.md).
3. **Обучение LoRA** на рисунках Милы и художников, давших согласие, — на Illustrious и Anima,
   локально. Готовые LoRA сразу появляются в интерфейсе.
4. **Сервер ComfyUI** для Krita на Mac и для Claude Code (comfyui-mcp).

Ставим по слоям: Windows → ComfyUI → модели → скрипт генерации и сравнение (готово) →
каталог моделей, LoRA и предпромптов → веб-интерфейс с Claude → удаление фона, спрайты,
обучение, экспорт в игру, Krita, comfyui-mcp. Каждый шаг заканчивается проверкой.

**Сравнение моделей делаем на MSI** (решение Павла, 07.11.2026) — шаг 4, сразу после настройки
ComfyUI. Здесь оно займёт ≈ 30–60 мин вместо ≈ 6,5 ч на Mac. Весь прогон — в одном движке
(ComfyUI); превью Mac на Anima Turbo с ним по seed не сравниваем.

**Диск.** Правило: держать ≥ 30 ГБ свободными (файл подкачки, кэш, временные файлы). Перед
каждой новой моделью — проверить место; не хватает — удалить то, что не используется
(проигравшие в сравнении модели, кэш pip / uv, старые прогоны после переноса через
веб-интерфейс).

**Веб-интерфейс** ([web-interface/](../../../web-interface/README.md)) живёт **на MSI**, рядом
с ComfyUI и главной копией `content/`. Открывается в браузере с ноутбука, планшета или
телефона в домашней сети. Он же — способ передавать `content/` между машинами. Шаги 6–7.

**Первая версия — быстро и просто.** Цель — как можно раньше посадить Милу за интерфейс и
понять, чего не хватает, что удобно и что нет. Поэтому v1 собираем вехами (шаг 6): каждая
веха — рабочий интерфейс, который можно показать.

### ☑ 2. ComfyUI

- ☑ **ComfyUI portable v0.44.0** (сборка для NVIDIA, 04.11.2026) в `C:\AI\ComfyUI\`, а не
  ComfyUI Desktop. Внутри: Python 3.13.14, PyTorch 2.14.1 + CUDA 13.0, фронтенд 1.57.6. Занимает
  ≈ 5,5 ГБ. Архив 7z распаковывается системным `C:\Windows\System32\tar.exe`, 7-Zip не нужен.
  Почему portable:
  - одна папка: модели, ноды, выход — всё в ней, видно, сколько занимает, легко чистить;
  - запуск из `.bat` с явными флагами (`--listen`, порт, путь вывода) — так же из скрипта и
    для Krita;
  - встроенный Python — не конфликтует с окружениями тренеров.
- ☑ Свой батник запуска [msi/scripts/comfy_start.bat](../../../msi/scripts/comfy_start.bat):
  без аргументов — только localhost, `lan` — домашняя сеть. Батник — только ASCII и CRLF: с
  кириллицей в UTF-8 и LF cmd разбирает его по кускам (в `.gitattributes` закреплено
  `*.bat eol=crlf`).
- ☑ ComfyUI-Manager **4.2.2** — теперь встроен в ComfyUI: пакет из
  `ComfyUI/manager_requirements.txt` во встроенный Python и флаг `--enable-manager` (есть в
  батнике). Отдельно клонировать в `custom_nodes` не нужно.
- **Проверка:**
  - ☑ `http://127.0.0.1:8188` отвечает через 35 с после запуска; `/system_stats` видит RTX 4060,
    свободно 7,45 ГБ VRAM; API менеджера отвечает (`/v2/manager/version` → V4.2.2);
  - ☑ картинка через API: Anima Turbo v1.1, `mark-room-night`, 1344×768 — 20 с холодным, 8,3 с
    с загруженной моделью, пик VRAM 6,1 ГБ; картинка связная и по промпту

### ◐ 5. Каталог: модели, LoRA, предпромпты

Всё, из чего собирается генерация, описано в файлах репо: и веб-интерфейс, и
`comfy_generate.py` читают одни и те же файлы. Набор будет расти: Павел собирает модели и LoRA,
которые кажутся подходящими, мы проверяем их на наборе bake-off, решение за Павлом.

- ☑ **Каталог в `msi/catalog/`**: `models.json` переезжает сюда из `msi/scripts/` (скрипт и доки
  поправить) и получает поля для интерфейса:
  - `title` и `hint` по-русски — «Фоны, лучшее качество, ≈ 45 с», «Быстрый черновик, 8 с»;
  - `good_for`: `backgrounds` / `sprites` / `drafts`;
  - `negative_works`: работает ли негатив (при CFG 1 — нет, интерфейс тогда прячет поле и
    объясняет почему);
  - `sizes`: какие размеры родные.
- ☑ **LoRA — `msi/catalog/loras.json`** (файл заведён, список пока пуст). Файлы лежат в `C:\AI\ComfyUI\ComfyUI\models\loras\`,
  по каждой записано:
  - файл, семейство (`illustrious` / `anima` / `flux`);
  - название и «для чего» по-русски;
  - триггер-слова, сила по умолчанию и разумный диапазон;
  - откуда (ссылка) и лицензия.

  Файл, который лежит в папке, но не описан, интерфейс всё равно показывает — с пометкой «без
  описания».
- ☑ **Предпромпты — `prompts/blocks.json`**. Блок — кусок промпта, который включается и
  выключается галочкой. У блока есть:
  - `id`, название и подсказка по-русски;
  - группа: стиль / качество / мир / кадр;
  - текст для каждого семейства моделей (позитив и негатив);
  - к чему относится: фоны / спрайты / всё;
  - включён ли по умолчанию.

  Теги блока (`tags`) всегда идут перед промптом, фразы (`text`) — до или после него, позиция
  своя для каждого семейства: Anima нужны сначала теги, потом предложения.

  Стартовый набор — из того, что уже проверено в bake-off:
  - «Качество» — префикс и негатив модели из `models.json`, отключаемый;
  - «Semi-realism» — стиль;
  - «Палитра мира: ночь» — пурпурный неон, янтарные фонари, сине-фиолетовые тени, film grain;
  - «Фон без людей»;
  - «Спрайт: полный рост на белом»;
  - «Без текста».

  Дальше блоки доводим вместе с Павлом и Милой; хорошие находки из дневников задач (шаг 7)
  переносим сюда.
- ☐ **Персонажи и места как блоки** — промпт-ядра из карточек
  [vibe-description/](../../vibe-description/README.md): «Персонаж: Марк», «Место: кафе».
  Карточки остаются источником, блоки собираются из них.
- ☐ `comfy_generate.py` понимает LoRA и блоки в файле прогона — чтобы проверять находки на
  всём наборе bake-off одной командой.
- ☐ `msi/scripts/contact_sheet.py` — листы «модели × seed» по прогону (как листы bake-off,
  которые сейчас собраны вручную). Потом это же — режим «сравнить» в интерфейсе.
- ☐ **Новые чекпойнты и LoRA от Павла:** скачать → проверить хеш → записать в каталог →
  прогнать набор bake-off → лист → решение Павла. Не прошедшие проверку удаляем: держим ≥ 30 ГБ
  свободными.
- ☐ Доводка промптов bake-off по итогам первого среза: `cafe-day` — явно изнутри,
  `alley-night` — вид сверху вниз, для WAI — меньше фиолетового.
- **Проверка:** в интерфейсе видны все модели с подсказками, LoRA фильтруются по модели,

### ◐ 6. Веб-интерфейс v1 — рабочее место Милы

Как устроен и как выглядит — [web-interface/README.md](../../../web-interface/README.md): там
сценарий, экраны, папки и API. Здесь — порядок работ.

**Основной сценарий.** Мила садится с задачей («нарисовать персонажа X»):

1. заводит задачу, прикладывает концепт, референсы, свои наброски (можно сфотографировать
   набросок телефоном);
2. пишет промпт, выбирает модель (интерфейс подсказывает, какая для чего), включает нужные
   LoRA и предпромпты;
3. видит очередь, прогресс-бар и примерное время до конца;
4. получает картинки, отмечает понравившиеся, убирает фон, скачивает, берёт картинку за
   основу для следующей;
5. всё, что она принесла и получила, лежит в `content/prototype/<задача>/`, а Claude ведёт
   дневник задачи: идеи, решения, что пробовали и что понравилось (шаг 7);
6. когда персонаж готов, по нему рисуется набор спрайтов в том же виде (шаг 8).

**Решения по устройству** (подробно и с причинами — в README):

- Сервер — Python (FastAPI + uvicorn) через `uv`, своё окружение в `web-interface/`. Фронтенд —
  HTML, CSS и JS без сборки и без CDN: работает без интернета, править просто. Node не нужен.
- Интерфейс по-русски, сначала под телефон, потом шире: ноутбук, планшет, телефон.
- **ComfyUI остаётся на `127.0.0.1`**: с ним говорит только сервер интерфейса. В домашнюю сеть
  смотрит один порт интерфейса (8000), правило брандмауэра — только для частной сети.
- Вход — общий пароль из `web-interface/.env` (не в git) и выбор «кто я» (Мила, Павел…) — для
  дневника. Пароль нужен, потому что интерфейс запускает Claude и пишет файлы.
- Генерирует через API ComfyUI, графы собирает один общий модуль. `comfy_generate.py` потом
  переходит на него же, чтобы у скрипта и интерфейса были одинаковые картинки.
- Прогресс — сервер слушает websocket ComfyUI (шаги сэмплера, загрузка модели, декодирование),
  браузер опрашивает сервер раз в 1–2 с. На телефоне так надёжнее, чем держать соединение.

### ◐ 7. Claude в веб-интерфейсе

Сервер запускает Claude Code без интерфейса (`claude -p`, на MSI стоит CLI 2.1.319, подписка
Павла):

- рабочая папка — репо;
- инструменты ограничены: чтение и запись только в папке задачи и в `content/prototype/`,
  чтение карточек `.claude/vibe-description/` и `prompts/`, без Bash и без сети;
- Claude стартует только когда очередь генерации пуста: при 16 ГБ RAM он не должен мешать
  FLUX;
- сбой Claude генерацию не останавливает;
- каждый запуск Claude (сколько шёл, что изменил) записывается в `log.jsonl`.

- ☑ **7.1. Дневник задачи** (входит в v1). `claude -p --restricted`, рабочая папка `content/prototype/`, инструкция — `web-interface/claude/journal.md`.
  - Когда в задаче что-то новое (загрузки, заметки, генерации, ★ и «финал»), после паузы
    ≈ 1–2 мин или по кнопке «подвести итог» Claude читает новые записи `log.jsonl`, смотрит
    новые картинки и обновляет `notes.md`:
    - концепт и идеи Милы — её словами;
    - референсы — что в них важно;
    - что пробовали: модели, LoRA, блоки, промпты;
    - что понравилось и почему (по ★ и «финал»);
    - открытые вопросы, следующий шаг.
  - Интерфейс показывает дневник на странице задачи и статус «Claude пишет дневник…».
  - Сводка по всем задачам — `content/prototype/README.md`.
- ☐ **7.2. Документы проекта.** Когда задача дошла до «финала», Claude готовит правку карточки
  персонажа или места в `.claude/vibe-description/` — файлом `card-proposal.md` в папке задачи.
  Павел переносит и коммитит. Сами карточки Claude не меняет: они в git, а `sources/` — дословные
  тексты Павла.
- ☑ **7.3. Помощник промпта** (входит в v1). Без инструментов, карточки и правила — в запросе; инструкция — `web-interface/claude/prompt-helper.md`. Мила пишет идею по-русски, своими словами. Claude
  собирает промпт под семейство выбранной модели по правилам
  [prompts/bake-off.md](../../../prompts/bake-off.md): теги для Illustrious, теги и текст для
  Anima, полные фразы для FLUX. Учитывает карточку персонажа или места и включённые блоки.
  Мила правит результат в форме, всё пишется в дневник.
- ◐ **7.4. Подсказки по моделям и LoRA.** В v1 — статичный текст из каталога. Позже Claude
  советует по задаче: «для фона ночного переулка — Aesthetic + блок „Палитра мира“».
- **Проверка:** после сессии Милы в `notes.md` понятным языком записано, что она хотела, что
  пробовала и к чему пришла; Павел, не спрашивая Милу, понимает состояние задачи.
